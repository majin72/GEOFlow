# GEO 监测合规使用说明

GEOFlow 的 GEO 监测能力是开源研究工具，用于帮助使用者在自有账号、自有品牌和低频测试场景下，观察公开 AI 产品回答中的品牌可见度与引用来源。项目本身不提供豆包、DeepSeek、腾讯元宝等第三方平台的数据转售、代采集或商业化监测服务。

本说明不是法律意见。不同国家、地区、平台服务条款和具体使用方式可能导致不同合规结论。使用者在启用 GEO 监测前，应自行确认其账号、访问方式、数据处理和业务目的符合适用法律法规及目标平台规则。

## 允许的使用边界

- 使用者应仅使用自己有权使用的账号、网络环境、品牌名称、关键词和测试问题。
- 建议仅用于内部研究、产品验证、低频质量检查和自有品牌 GEO 可见性评估。
- 探测频率应保持克制，避免对第三方平台造成异常负载、干扰或规避访问限制。
- 遇到验证码、安全验证、登录失效、风控提示或平台拒绝访问时，应停止自动探测并人工处理。
- 采集结果应优先保存必要的统计信息，例如平台、时间、prompt、引用 URL、引用域名、是否命中自有域名和状态码。

## 禁止或不建议的使用方式

- 不得将本工具用于绕过验证码、安全验证、登录限制、访问频控或其他平台风控措施。
- 不得接入打码平台、批量账号池、代理池滥用、指纹伪装滥用或其他规避访问控制的能力。
- 不得大规模抓取、复制、转售、公开分发第三方平台的回答正文、页面 HTML、截图或派生数据集。
- 不得使用未授权账号、购买账号、共享账号或违反账号注册协议的登录凭据。
- 不得把本工具包装成面向第三方平台的商业化数据采集、数据售卖或自动化监控服务。
- 不得通过本工具提交违法、侵权、涉密、含个人敏感信息或超出授权范围的内容。

## 证据与数据最小化

GEO 监测可以保存截图、HTML、纯文本、JSON 和报告，便于调试 selector、复核引用来源和排查运行问题。生产或长期使用时，建议按最小化原则处理：

- 优先保留引用 URL、域名、标题、命中状态、运行时间和错误状态。
- 回答全文、页面 HTML、截图等证据应设置短留存周期，或仅在失败、验证码、selector 失效等排障场景保存。
- 若 prompt、回答或截图包含客户信息、个人信息、商业秘密或未公开资料，应进行脱敏、访问控制和定期清理。
- 不应把第三方平台页面截图、完整回答或 HTML 作为公开报告内容对外展示。

## 账号与运行环境

- 每个平台账号应由使用者自行登录和维护，项目不内置账号、cookie、token 或第三方平台凭据。
- `profiles/` 目录可能包含登录态和浏览器缓存，应视为敏感数据，不应提交到 Git、镜像或公开附件。
- `accounts.json` 中的代理、账号标识和 profile 路径应妥善保管，不应公开。
- noVNC 和 sidecar API 仅应暴露在本机、内网或受控隧道中，生产环境必须配置访问鉴权。

## 默认安全策略

项目推荐保持以下默认策略：

- sidecar 通过 `geo-monitor` profile 按需启用，未显式启用时不运行。
- 生产模式使用低频、无头、非交互运行；检测到验证码时快速失败并告警。
- 不提供自动破解验证码、自动规避风控或绕过平台限制的实现。
- 运行命令保留 `--delay-seconds`，避免连续高频请求。
- 证据目录、浏览器 profile、账号配置和 noVNC 状态文件默认不提交到版本库。
